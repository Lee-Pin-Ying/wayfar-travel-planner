# 旅序 Wayfar — 把旅行，慢慢安排成喜歡的樣子

> 互動旅遊規劃 Web App｜Vibe Coding 作業規格書
>
> 規格版本：1.1 · 2026-10-14
> 狀態：第一版已實作，可本機試用；尚未部署 GitHub Pages。驗收清單保留為完整目標，實際驗證範圍見 TESTING.md。

## 快速開始

1. 用瀏覽器開啟同目錄的 `index.html`，或使用本機靜態網站伺服器。
2. 首頁點選「體驗台南示範」查看完整範例；也可以直接建立自己的旅程。
3. 在「旅程設定與備份」編輯資料、匯出與匯入；手機使用右上角的編輯圖示。
4. 本機檔案、localhost 和 GitHub Pages 的儲存空間互不相通；搬移前先匯出，再於新網址匯入。
5. 核心邏輯測試可使用 `node tests.cjs`。

本版已支援國內／國外旅程、外幣手動匯率及跨日／跨時區交通。以各筆消費保存的匯率換算台幣統一結算。

## 1. 專案理念

旅行的準備往往散落在待辦清單、地圖、訂房紀錄與記帳工具之間。旅序將「決定出發 → 行前準備 → 安排行程 → 旅途中使用 → 回家結算」串成一個完整流程。

使用者可以建立旅程、產生打包清單、安排每日活動、整理交通與住宿、記錄共同支出及追蹤伴手禮。網站以旅行雜誌般的視覺與直覺操作，降低整理資訊的負擔。

### 目標使用者

- 想自行安排國內短程旅行的學生與朋友。
- 習慣記錄旅行資訊，但不想從空白表格開始的人。
- 出門前想確認是否準備齊全、旅途中想快速找到資訊的人。

### 成功標準

第一次使用的人，能在三分鐘內建立旅程、產生打包清單並新增第一個行程；回到網站時，資料仍然存在。桌機適合規劃，手機適合隨身查閱。

## 2. 參考內容與設計轉譯

需求參考使用者提供的 Notion 旅遊頁面，以及其中的任務、交通、行程、記帳與代購資料庫欄位。僅採用流程與資訊結構，公開專案不包含原始私人頁面連結、實際帳目、同行者資訊、訂單或未取得使用權的照片。

| 原有資訊 | 網站呈現 | 改善方向 |
| --- | --- | --- |
| 旅程日期、人數、狀態 | 旅程封面與摘要 | 第一眼知道何時出發、還缺什麼 |
| 任務清單、行前訂票 | 行前待辦 | 期限、優先度、完成進度清楚可見 |
| 必備物品 | 分類打包清單 | 依天數和活動產生建議，可自行調整 |
| 去程、回程、住宿 | 行程中的交通與住宿卡片 | 同一筆資料依類型呈現，避免重複維護 |
| 每日景點、用餐、時間、地圖 | 每日時間軸 | 用日期切換，依時間排序，點擊開啟地圖 |
| 消費、付款人、分帳狀態 | 旅費與分帳 | 自動計算總額與每人的應收應付 |
| 代購品項、價格、購買地點 | 伴手禮清單 | 加入受託對象、購買及交付狀態 |

## 3. 作業限制與技術範圍

- 最終網站集中於單一 `index.html`；HTML、CSS、JavaScript 均寫在其中。
- 使用原生 HTML、CSS、JavaScript，不需要建置流程或安裝套件。
- 可直接開啟檔案使用核心功能，亦可作為靜態網站部署至 GitHub Pages。
- 採繁體中文介面；可設定常用消費幣別，外幣消費以手動匯率換算 TWD 統一結算，不查詢即時匯率。
- 資料保存在目前瀏覽器的 localStorage，不需帳號、伺服器或資料庫。
- 提供 JSON 匯出與匯入，方便備份與換裝置；不宣稱即時同步或多人協作。
- 圖示及裝飾使用內嵌 SVG、CSS；採系統字型，核心畫面不依賴遠端資源。
- 地圖為使用者主動開啟的外部連結，不嵌入地圖 API、不要求 API 金鑰。
- 網站不直接串接 Notion；Notion 僅為需求參考。
- AI 用於討論與開發；打包建議採明確規則，不宣稱由線上 AI 即時生成。

## 4. 資訊架構與主要流程

```text
首次進入：建立旅程 / 體驗示範旅程
  └─ 旅程工作區
      ├─ 總覽：封面、倒數、進度、下一步
      ├─ 行前：訂票待辦、分類打包清單
      ├─ 行程：日期切換、活動時間軸、交通住宿
      ├─ 旅費：支出、預算、分類統計、分帳結算
      └─ 伴手禮：待買、已買、已交付

共用操作：切換旅程、編輯旅程、備份、匯入、刪除
```

### 典型情境

1. 使用者建立「台南慢遊」，設定三天兩夜與三位同行者。
2. 選擇城市、美食及跑步活動，取得可編輯的打包建議。
3. 新增訂車票、訂住宿等待辦，設定期限並逐一完成。
4. 在第一天新增去程交通、午餐、景點及住宿，透過時間軸查閱。
5. 出發前查看剩餘打包項目；旅途中以手機切換當日行程及地圖。
6. 新增共同支出，選擇付款人與參與分攤的人。
7. 回家後查看結算、標記還款，完成伴手禮交付並匯出旅程。

## 5. 功能規格

### F01｜旅程建立與管理

- 可建立、切換、編輯及刪除多個旅程。
- 欄位：旅程名稱、目的地、國內／國外、開始日期、結束日期、同行者暱稱、總預算、常用消費幣別、活動標籤。第一版固定採墨綠主題。
- 必填名稱、目的地、起迄日期及至少一位同行者；預算可留空。
- 日期採日曆日期計算，含首尾兩天；同日旅行為一天。第一版支援 1–30 天。
- 結束日期不得早於開始日期，預算不得為負數。
- 同行者以穩定 ID 識別；第一版以暱稱清單增減同行者。同一旅程不可重複；已有帳務的成員暫不支援直接改名。
- 已被支出或還款引用的同行者不可直接刪除，需先處理相關紀錄。
- 縮短旅程日期時，超出範圍的行程保留並標示「日期需調整」，不靜默刪除。
- 刪除旅程需明確確認，並提供先匯出備份的入口。

### F02｜旅程總覽

- 主視覺顯示目的地、旅程名稱、日期、天數、同行人數及旅程階段。
- 出發前顯示倒數；旅行中顯示第幾天；結束後顯示旅程已結束。
- 顯示行前待辦完成比例、打包完成比例、實際支出及預算餘額。
- 準備完成率＝已完成待辦與打包項目數 ÷ 全部待辦與打包項目數；零項目時顯示「尚未建立清單」。
- 「下一步」優先顯示逾期待辦，其次最近到期的未完成待辦，再提示未打包物品。
- 旅行中顯示當日行程摘要；非旅行期間顯示第一天預覽，標題明確區分。
- 快速入口：新增行程、新增支出、繼續打包。

### F03｜行前任務與訂票

- 可新增、編輯、刪除與勾選任務。
- 欄位：標題、分類、期限、優先度、備註、完成狀態。
- 分類包含交通、住宿、票券、其他；優先度為高、中、低。
- 建立旅程時提供訂住宿、安排去程、安排回程等可修改的範例任務。
- 篩選全部、未完成、已完成；未完成且期限早於今天時顯示逾期。
- 完成後更新進度，不因自動排序立即移動正在操作的項目。
- 任務僅管理準備狀態，不代表網站已代為訂票或付款。

### F04｜打包清單產生器

- 基本分類：證件與金錢、衣物、盥洗保養、電子用品、活動用品、其他。
- 依旅程天數與活動標籤產生建議，每項可調整名稱、分類及數量。
- 基本規則：上衣與內著各為天數份，襪子為天數雙，褲子為向上取整的天數除以二件；全部可自行修改。
- 基本物品包含證件、錢包、手機、充電器、牙刷與牙膏。
- 海邊加入泳衣、防水袋；登山加入登山鞋、雨具；跑步加入跑步服與跑鞋；親子加入兒童備用衣物與濕紙巾。
- 新建議透過穩定的範本鍵去重，保留既有勾選、自訂項目及手動修改數量。
- 日期或活動變更後提示可到行前準備「補入建議」，不覆蓋現有清單；國外旅程額外建議護照、外幣與轉接頭。
- 每項可新增、修改、刪除、勾選；可依分類及未完成狀態篩選。
- 打包進度按項目計算，不按數量加權；數量至少為 1 的整數。
- 全部完成時顯示簡短完成回饋；不持續播放動畫。

### F05｜每日行程、交通與住宿

- 日期分頁顯示 Day 1、Day 2 及實際日期，手機可水平捲動。
- 可新增、編輯、刪除與標記活動完成。
- 欄位：標題、日期、開始時間、結束時間（選填）、類型、地點或地址、地圖網址（選填）、預估費用、備註。
- 類型包含去程、回程、當地交通、住宿、美食、景點、其他。
- 交通卡片額外顯示出發地、抵達地及班次備註；住宿以備註記錄入住資訊。
- 有時間的活動依時間排序，同時間依建立順序；無時間的活動置於「時間未定」。
- 一般行程結束時間不得早於開始時間；跨日／跨時區交通可勾選額外欄位，填寫抵達日期、出發與抵達時區，換算後的抵達時間不得早於出發。
- 一般活動有完整起迄時間且發生重疊時顯示提示，允許使用者保留安排；跨時區交通暫不納入重疊提示。
- 可依類型篩選；地圖按鈕開啟有效的 HTTP(S) 網址，未填網址時以地點文字產生地圖搜尋連結。
- 行程預估費用與旅費實際支出分開計算，避免重複加總。
- 空白日期提供「安排第一站」入口。

### F06｜旅費與預算

- 支出可新增、編輯、刪除；欄位為項目、日期、原幣金額、幣別、手動匯率、分類、付款人、分攤成員及備註。
- 外幣以「1 原幣 = 幾 TWD」的匯率逐筆儲存，換算台幣四捨五入至分；後續修改其他筆匯率不改動舊帳。
- 金額須大於零、最多兩位小數；內部換算成整數分儲存，避免浮點誤差。
- 分類包含餐飲、交通、住宿、門票、購物、其他。
- 每筆支出只有一位付款人，可勾選一位以上的分攤成員；付款人不必參與分攤。
- 顯示總支出、預算餘額與分類長條圖；沒有預算時顯示「尚未設定」。
- 超出預算時以文字與顏色提示超出金額，不只依賴顏色。
- 支出列表支援分類篩選；統計明確標示為全旅程總額，不隨列表篩選改變。

### F07｜分帳與結算

- 第一版採每筆支出在勾選成員間平均分攤。
- 以分為單位除算，餘數依旅程成員順序逐一分配，分攤合計必須等於支出金額。
- 每位成員淨額＝已付款－應分攤額＋已還款－已收到還款；正數為應收，負數為應付。
- 依淨額配對產生「誰付給誰多少錢」的結算建議，不承諾付款筆數最少。
- 標記完成一筆建議時，建立獨立還款紀錄，記錄付款人、收款人、金額及日期；可刪除以撤銷。
- 還款不算入旅費總支出；編輯支出後重新計算餘額，保留已發生的還款。
- 全部淨額為零時顯示「已結清」。

### F08｜伴手禮與代購

- 可新增、編輯、刪除品項。
- 欄位：品名、受託對象暱稱、數量、購買地點、預估總額、實際總額及備註。
- 狀態為待購買、已購買、已交付，可切換並篩選。
- 已交付代表已購買；退回待購買不自動清空已填金額。
- 顯示未購買與未交付的數量摘要。
- 此區金額僅供採買追蹤，不自動計入共同支出；需要記帳時由使用者另新增支出。

### F09｜儲存、備份與示範

- 所有有效修改立即保存；頁面顯示已儲存或儲存失敗狀態。
- localStorage 無法使用或容量不足時，不顯示假成功；保留當前記憶體資料並提供匯出。
- 第一次進入提供「建立我的旅程」與「體驗台南示範」兩個入口。
- 示範使用虛構暱稱與金額，清楚標註「示範資料」，可修改及刪除。
- 匯出目前旅程為帶版本的 JSON，含所有子資料與還款紀錄。
- 匯入前檢查檔案大小（上限 2 MB）、版本、必要欄位、日期、數值、ID 唯一性及關聯完整性。
- 匯入以新旅程副本加入，重新對映 ID；不覆蓋既有旅程。
- 無效檔案顯示可理解的錯誤，不部分寫入；未知版本拒絕匯入。
- 提醒使用者資料只在此瀏覽器，清除網站資料會移除紀錄；跨裝置以匯出入移轉。
- 備份可能含個人資訊，不建議將自己的備份提交至公開儲存庫。

## 6. 視覺設計規格

### 設計概念：溫暖的旅行編輯手帳

以奶油白紙感、大標題、墨綠導航與暖橘重點，呈現悠閒但有秩序的旅行氛圍。首頁以內嵌線條風景插畫、旅程標題及日期構成封面，其餘畫面以清楚資訊為主。

| 設計項目 | 規格 |
| --- | --- |
| 背景 | 暖白 `#F7F5EF` |
| 主要文字 | 深墨綠 `#233D35` |
| 主按鈕 | 深綠 `#31594A`，白字 |
| 強調色 | 暖橘 `#C66A3D`，用於進度與裝飾；小字需另驗證對比 |
| 次要文字 | 灰綠 `#65716A` |
| 邊框 | 淡灰綠 `#DFE4DC` |
| 中文字型 | 系統黑體；大標題可使用系統宋體備援 |
| 數字 | 使用等寬數字，減少金額與進度更新時的跳動 |
| 間距 | 以 8 px 為基準；區塊間 24–40 px |
| 圓角 | 按鈕 12 px，主要面板 20–24 px |
| 陰影 | 輕微且低透明度，主要以留白及邊框區隔 |
| 圖示 | 統一線條式 SVG，每個純圖示按鈕均提供文字標籤 |

### 版面

- 桌機（≥ 1100 px）：左側固定導航，右側內容最大寬度約 1180 px；總覽可有主內容與摘要側欄。
- 平板（768–1099 px）：縮窄導航及間距，內容依空間調整為一至兩欄。
- 手機（< 768 px）：單欄內容、底部五個主要分頁，預留安全區與底部空間；避免按鈕遮住最後一筆資料。
- 手機表單使用大面積對話框或底部面板，內容可捲動，儲存按鈕始終可觸及。
- 日期列可單獨水平捲動；整頁不可出現非預期水平溢出。

### 「絲滑」的具體標準

- 按鈕 hover/press 回饋約 120–180 ms。
- 分頁與面板切換約 180–240 ms，以 opacity 與小幅 transform 為主。
- 勾選後立即更新狀態與進度，動畫不延遲資料保存。
- 同一次點擊只執行一次新增或儲存，防止連點重複提交。
- 不劫持捲動、不加入持續漂浮或大量粒子動畫。
- 使用 `prefers-reduced-motion` 時取消非必要位移與動畫。
- 操作回饋簡短明確，例如「已加入行程」「已儲存」；錯誤訊息保留至修正。

## 7. 無障礙與操作細節

- 按鈕最小觸控區域 44 × 44 px；正文依資訊層級約 12–16 px。
- 一般文字對比目標至少 4.5:1；所有焦點狀態明顯可見。
- 表單欄位有標籤，必填與錯誤訊息相互關聯。
- 鍵盤可完成導航、勾選、新增及儲存；選取分頁以 `aria-current` 或等效語意表達。
- 對話框打開時移入焦點、限制焦點在其中；Esc 可關閉並將焦點還給開啟按鈕。
- 未儲存的表單關閉前保留草稿或提示放棄。
- 成功通知以適當的 live region 宣告；不僅以顏色表達完成或錯誤。
- 沒有資料、沒有搜尋結果、全部完成與儲存失敗皆有專屬提示。

## 8. 資料模型

根狀態為 `{ schemaVersion: 1, activeTripId, trips: [] }`；每個旅程擁有以下資料。

| 實體 | 核心欄位 |
| --- | --- |
| Trip | id、title、destination、kind、startDate、endDate、budgetCents（可空）、currency、tags、theme、isDemo |
| Member | id、name |
| Task | id、title、category、dueDate、priority、notes、done |
| PackingItem | id、templateKey（可空）、name、category、quantity、packed |
| Activity | id、title、date、startTime、endTime、type、place、mapUrl、estimatedCents、notes、origin、destination、endDate、crossZone、departureZone、arrivalZone、done、createdAt |
| Expense | id、title、date、amountCents、originalAmount、currency、rate、category、payerId、participantIds、notes |
| Settlement | id、fromMemberId、toMemberId、amountCents、date |
| Gift | id、name、recipient、quantity、place、estimatedCents、actualCents、status、notes |

- 子資料陣列均儲存在旅程內，避免切換旅程時混用。
- 日期使用 `YYYY-MM-DD`，時間使用 `HH:mm`；一般行程以當地時間記錄，跨時區交通另保存出發與抵達 IANA 時區。夏令時間切換的重複時段仍須由使用者確認官方航班時間。
- 金額為整數分；畫面使用 TWD 格式顯示。
- UI 狀態如開啟中的對話框及列表篩選不納入匯出。
- 使用者輸入以文字節點呈現，不直接插入未轉義 HTML。
- 外部連結僅接受 HTTP(S)，新分頁連結設定適當的 `rel`。

## 9. 第一版邊界

本規格 F01–F09 均為第一版目標。優先確保功能閉環、資料正確與行動裝置操作，再打磨視覺。

以下留待未來版本：線上帳號與多人同步、AI 自動排程、即時天氣與匯率、訂票付款、地圖路線最佳化、照片上傳、推播提醒、不等額分攤、跨時區行程重疊檢查、即時匯率、完整離線 PWA。

第一版核心不依賴網路服務，但不保證網站在從未載入或清除快取後仍可離線開啟；外部地圖需要網路。

- [ ] 損毀檔案、未知版本及過大匯入檔案不污染現有資料。
